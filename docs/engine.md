# 조합 원리

LuminousKR이 자모 24자의 뼈대로 한글 11,172자를 만드는 과정과, 같은 방식으로 만드는 영문·숫자·문장부호 94자입니다. 코드는 `src/entities/font`와 `src/shared/lib`에 있습니다.

## 1. 뼈대 모델

자모는 획의 **가운데 선(뼈대)** 만 저장합니다(`model/types.ts`).

| 획 | 저장 값 |
|---|---|
| 경로 | 점 목록, 닫힘 여부(ㅁ처럼), 매끄러움(캣멀-롬 곡선) |
| 타원 | 중심, 가로·세로 반지름 (ㅇ, ㅎ) |

좌표는 자모가 놓이는 **틀(box)** 안에서 0~1로 정규화합니다. 틀 크기가 바뀌어도 그림이 따라갑니다.

프로젝트 파일은 2판입니다(`format: 'luminous-kr', version: 2`). 1판(1.x, 영문 없음)을 읽으면 영문을 비운 채 2판으로 바꾸고(`model/validate.ts`), 이 앱보다 새 판은 열지 않습니다.

## 2. 여섯 가지 배치

음절은 중성 모양과 받침 유무에 따라 여섯 틀 가운데 하나로 짜입니다(`model/layout.ts`의 `DEFAULT_LAYOUTS`).

| 배치 | 예 | 중성 | 받침 |
|---|---|---|---|
| A | 가 | 세로(ㅏ ㅐ ㅑ ㅒ ㅓ ㅔ ㅕ ㅖ ㅣ) | 없음 |
| B | 고 | 가로(ㅗ ㅛ ㅜ ㅠ ㅡ) | 없음 |
| C | 과 | 섞임(ㅘ ㅙ ㅚ ㅝ ㅞ ㅟ ㅢ) | 없음 |
| D | 각 | 세로 | 있음 |
| E | 곡 | 가로 | 있음 |
| F | 곽 | 섞임 | 있음 |

자모의 기본 그림은 **기본 배치**(초성 A, 세로 모음 A, 가로 모음 B, 섞임 모음 C, 종성 D)의 틀 기준이고, 다른 배치에서는 그 틀 크기에 맞춰 늘이거나 줄입니다. 선은 틀에 맞춰 늘이되, 타원은 기하 평균으로 크기를 맞추고 늘임을 1.12배까지로 제한해 ㅇ이 지나치게 납작해지지 않게 합니다.

특정 배치만 모양을 따로 그린 것을 **변형(벌)** 이라 하고, 있으면 그 배치에서 기본 그림 대신 씁니다. 옛 조합형 글꼴의 벌 개념과 같습니다.

## 3. 파생 규칙

직접 그리지 않은 43자는 다른 자모로 만듭니다(`model/derivation.ts`).

| 갈래 | 규칙 | 변형 이어받기 |
|---|---|---|
| 쌍자음 ㄲ ㄸ ㅃ ㅆ ㅉ | 같은 자음 둘을 좌우에 | 예 (같은 초성 자리) |
| ㅐ ㅒ ㅔ ㅖ | 세로 모음 + ㅣ | 예 |
| 섞임 모음 7자 | 가로 모음 → 배치의 Vh 틀, 세로 모음 → Vv 틀 | 아니요 |
| 홑받침 14자 | 같은 초성의 **기본 그림**을 받침 틀에 | 아니요 (초성 변형은 초성 자리용) |
| 쌍받침·겹받침 13자 | 받침 둘을 좌우에 (ㄺ = ㄹ + ㄱ) | 예 |

나란히 놓는 두 자모의 사이는 획 굵기에 비례합니다(`resolveOptionsFor`). 그림을 찾는 순서는 `배치 변형 → 기본 그림 → 파생 규칙`입니다(`lib/resolve.ts`).

## 4. 굵기 입히기와 곡선 맞춤

`lib/outline.ts`가 뼈대를 윤곽으로 바꿉니다.

1. **좌표 변환**: 음절 좌표를 글꼴 좌표(1em = 1000, y 위로)로. 획 바깥이 글자 너비·높이 안에 들도록 뼈대 범위는 굵기의 절반만큼 줄입니다.
2. **펼치기**: 매끄러운 경로는 구심 캣멀-롬 스플라인을 베지어로 바꿔 4단위 간격으로, 타원은 둘레 길이에 맞춰 점으로 펼칩니다.
3. **두께 입히기**: Clipper2의 오프셋(`ClipperOffset`)으로 끝 모양(둥근·각진·잘린)과 꺾임(둥근·뾰족·깎은)에 맞춰 부풀리고, 겹친 획은 하나로 합칩니다. 가로·세로 굵기 차이(대비)는 x축을 줄인 공간에서 같은 두께로 부풀린 뒤 되돌려 만듭니다(타원 펜 효과).
4. **곡선 맞춤**(`shared/lib/geometry/fit-curve.ts`): 오프셋 결과는 둥근 부분이 잘게 나뉜 다각형입니다. 1단위보다 가까운 점과 바늘처럼 튄 점(150°보다 크게 되돌아가면서 짧은 쪽 변이 8단위 미만, 정수 반올림에서 생김)을 지운 뒤, 긴 변은 직선으로 두고 짧은 변이 이어진 구간만 Schneider 알고리즘으로 3차 베지어에 맞춥니다. 직선과 곡선이 만나는 곳은 접선을 이어 매끄럽게 합니다.
5. **기울기·정수화**: 기울기는 글자 가운데 높이를 기준으로 기울이고, 좌표를 정수로 맞춥니다. 바깥 윤곽은 반시계(PostScript 규칙), 구멍은 시계 방향입니다.

굵기를 나중에 입히므로, ㄲ의 반쪽 ㄱ이나 받침 ㄹ처럼 작게 놓인 획도 다른 획과 두께가 같습니다.

바늘 규칙이 1.5.0까지는 꺾임만 보아, 두 변이 긴 좁은 틈(안쪽 각 30° 미만: 좁은 틀의 ㅅ·ㅈ·ㅊ 다리 사이, 영문 M의 기둥과 사선 사이)의 꼭짓점까지 지워 틈이 메워졌습니다. 2.0.0에서 짧은 변 조건을 더해 고쳤습니다(기본 글꼴 1,031자의 잘못 채운 곳이 열림).

## 5. 음절 조합과 캐시

`lib/composer.ts`의 `Composer`는 `자모 × 배치`마다 윤곽을 한 번만 계산해 둡니다(최대 약 250개). 음절은 초성·중성·종성 조각을 모아 만들고, 조각의 다각형 경계가 서로 겹칠 때만 다시 합쳐 곡선을 맞춥니다. 섞임 모음처럼 떨어진 조각이 있는 자모는 다각형마다 경계를 따로 비교해, 쓸데없이 다시 합치지 않게 했습니다(조합 3.2초 → 0.6초).

편집하면서 보는 미리보기 워커는 판(revision)이 바뀌어도 `ComponentCache`를 이어 씁니다. 자모×배치 윤곽은 **입력(배치한 획·획 스타일·글자 틀)이 같으면** 다시 계산하지 않고, 음절은 조각이 모두 같으면 합친 윤곽을 다시 씁니다. 점 하나를 옮기면 그 자모와 그 자모로 만드는 자모(ㄴ → 받침 ㄴ·ㄵ·ㄶ)만 다시 만들어, 자모 판 67자 + 588자 표 계산이 84 → 3 ms로 줄었습니다(획 스타일을 바꾸면 모두 다시 계산). 11,172자 전체 글꼴은 한 번만 만들므로 음절을 캐시에 담지 않습니다.

## 6. 영문·숫자·문장부호

ASCII 인쇄 글자 94자(U+0021–007E)도 뼈대만 저장하고 같은 획 스타일로 두께를 입힙니다(`model/latin.ts`, `model/latin-preset.ts`).

| 항목 | 값 |
|---|---|
| 뼈대 틀 | 글자마다 정사각 비율. y는 0(어센더)~1(디센더)로 아래로 커지고, x도 같은 단위(틀 높이 = 1)라 너비를 바꿔도 그림이 늘어나지 않음 |
| 안내선 | 어센더 0, 대문자 높이 1/12, x높이 1/3, 기준선 5/6, 디센더 1 (격자 24칸에서 0·2·8·20·24칸) |
| 글꼴 단위 | 획 바깥 기준 어센더 790, 디센더 −145. 뼈대 틀은 그 안으로 가로획 굵기의 절반만큼 들어와(`lib/outline.ts`의 `latinFrame`) 굵기를 바꿔도 획 바깥이 그 높이를 지킴. 기본 굵기에서 기준선 0, x높이 500, 대문자 높이 약 717 |
| 너비 | 글자 너비 = 뼈대 너비 × 틀 높이 + 세로획 굵기 + 좌우 여백 × 2. 곧은 옆면은 틀 안에 0.03 여백을 두어 둥근 글자 사이보다 조금 넓게 띄움. 숫자는 모두 0.54(표의 자리 맞춤) |
| 기본 뼈대 | 원과 직선으로 짠 기하학적인 한 굵기 글자체. 곡선은 6°마다 점을 둔 꺾은선으로, 직선과 이어지는 곳은 한 획 안에서 이어 끝 모양(둥근·각진·잘린)과 상관없이 이음매가 매끈함. 자유 곡선(& { } ~)만 매끄러운 곡선 획 |
| 저장 | 고친 것만 `latin: { [글자]: { drawing?, width? } }`. 없으면 기본 뼈대·기본 너비. 획을 모두 지운 글자는 글꼴에 넣지 않음 |

## 7. 글꼴 파일

| 항목 | 값 |
|---|---|
| 글리프 | `.notdef`, 빈칸(U+0020·줄바꿈 없는 빈칸 U+00A0), 영문·숫자·문장부호 94자(U+0021–007E, 내보내기에서 뺄 수 있음, 글자마다 너비가 다름), 호환 자모 51자(U+3131–3163), 한글 음절 11,172자(U+AC00–D7A3) |
| 윤곽 | CFF(PostScript), opentype.js `Font.toArrayBuffer()`. 음절은 자모 조각을 같은 자리에 그대로 놓아 만들어 윤곽 55,428개 가운데 서로 다른 몸체가 365개뿐이므로, 윤곽마다 시작점 이동(rmoveto) 뒤의 몸체를 잘라 두 번 이상 나오는 것을 전역 서브루틴(296개)으로 옮기고 callgsubr로 부름(`shared/lib/font-file/cff-subrs.ts`, Node에서 0.2초). OTF 3.8MB → 0.63MB, fontTools로 그린 11,225자 윤곽·너비가 옮기기 전과 같음 |
| 세로 기준 | 1em = 1000, 위 880, 아래 −120, 글자 몸은 가운데 380 기준. 글꼴의 줄 높이 값(typo·hhea)을 1em(위 880·아래 −120, 줄 사이 0)으로 맞추고 OS/2 4판 USE_TYPO_METRICS를 켬. 실제 줄 높이는 앱과 설정(웹의 CSS `line-height` 등)에 따라 달라짐. Windows 잘림 기준(usWin)은 글자 몸과 실제 글리프 범위 가운데 큰 쪽이라, 글리프가 글자 몸을 넘으면(크게 기울이거나 아주 굵게) usWin 값을 줄 간격에 쓰는 일부 옛 Windows 앱에서는 줄 간격이 넓어질 수 있음 |
| 이름 | Windows(유니코드) 레코드만: 영문 이름(0x0409) + 한국어 이름(0x0412), PostScript 이름, typographic family(16·17). 비운 값은 쓰지 않음. opentype.js가 넣는 유니코드·Mac 플랫폼 이름과 Apple 전용 `ltag` 표는 빼고 다시 묶음(`shared/lib/font-file/sfnt.ts`, 표 체크섬·checkSumAdjustment 다시 계산) |
| OS/2 | 4판, 굵기 등급(획 굵기에서 환산), 한국어 완성형 코드 페이지, fsType 0(설치 가능), x높이·대문자 높이는 넣은 x·H 윤곽의 위 끝(없으면 500·704) |
| WOFF | 표마다 zlib(`CompressionStream('deflate')`)으로 압축, 줄지 않는 표는 그대로 (0.63MB → 약 164KB) |
| WOFF2 | `shared/lib/font-file/woff2.ts`. CFF라 glyf·loca 변환이 없어 모든 표를 '변환 없음'으로 두고, 표를 디렉터리 차례로 이어 brotli 한 덩어리로 압축(알려진 태그는 색인, 길이는 UIntBase128). 규격대로 DSIG는 빼고 head.flags 11번 비트를 켬. 압축기는 `brotli-wasm`(품질 9)을 WOFF2를 만들 때만 워커에서 받음(내장 `CompressionStream('brotli')`은 품질을 정할 수 없고 Chromium에는 없어 쓰지 않음). 서브루틴을 넣은 0.63MB → 약 114KB(서브루틴 전 3.8MB에서는 품질 9가 147KB, 품질 11이 127KB지만 Node에서도 13초로 100배쯤 느림) |
| 한 가족 | 굵기 등급(100~900)을 여럿 고르면 뼈대는 그대로 두고 그 등급의 획 굵기로 벌마다 만들어 ZIP 하나로(`shared/lib/zip`, deflate). Regular·Bold는 같은 가족 이름(ID 1)에 스타일 이름만 다르고 BOLD 비트·macStyle은 Bold에만, 그 밖의 굵기는 ID 1이 '가족 이름 굵기'이고 typographic family·subfamily(ID 16·17)로 한 가족에 묶임 |

전체 빌드는 Web Worker(`api/engine.worker.ts`)에서 돌고, 진행 상황을 256글리프마다 보냅니다. 미리보기용 작은 글꼴(입력한 글자만)은 다른 워커에서 만들어 `FontFace`로 등록합니다. 취소하면 워커를 끝내고 다음 요청 때 새로 띄웁니다(`shared/lib/worker-rpc`).
